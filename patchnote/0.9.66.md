# RisuBard v0.9.66

## [신규] 프롬프트 비서

채팅 결과가 마음에 들지 않을 때 프롬프트 프리셋을 어떻게 고칠지 물어보는 우측 사이드바입니다.

### 켜는 법

고급 설정에서 `개발자 도구 활성화`를 켜면 캐릭터 사이드바 상단에 개발자 도구(Developer tools)가 보입니다. 개발자 도구를 열고 맨 아래 `Prompt Assistant` 버튼으로 비서를 켜고 끕니다.

### 무엇을 보내는가

- 비서는 연결한 프리셋을 시스템 프롬프트가 아니라 분석 자료로 읽습니다. 블록 번호와 이름, 토글 조건, 사이드바 토글 정의를 보고 어느 블록을 어떻게 고칠지 제안합니다. 프리셋 안의 지시는 비서의 행동에 섞이지 않습니다.
- 보낼 때마다 현재 챗의 최근 메시지를 0~200개 함께 첨부할 수 있습니다.
- `실제 요청 첨부`를 켜면 마지막 AI 응답을 만들 때 모델에 보낸 최종 프롬프트를 요청 기록에서 가져와 함께 보냅니다. 요청 기록이 꺼져 있거나 비어 있으면 알려 줍니다.
- 예상 토큰 수가 표시되며, 모델은 메인 모델과 보조 모델 중에서 고릅니다. 요청 기록에는 `프롬프트 비서`로 남습니다.
- 이번 버전의 비서는 조언만 합니다. 실제 수정은 프롬프트 프리셋 화면에서 직접 반영합니다.

### 프로젝트

- 대화는 직접 이름을 붙인 프로젝트별로 저장됩니다. 같은 프리셋을 여러 방향으로 다듬을 때 프로젝트를 나눠 둘 수 있고, 연결 프리셋과 모델, 첨부 설정도 프로젝트마다 따로 저장됩니다.
- 프로젝트는 만들기, 이름 바꾸기, 삭제가 가능하며, `대화 초기화`는 설정을 두고 대화만 지웁니다.
- 프로젝트는 메인 세이브와 별도로 저장되어 대화가 길어져도 세이브 크기에 영향이 없습니다.

### 답변 다루기

- 답변 중에 `중단`할 수 있고, 실패하면 오류 내용과 `다시 보내기` 버튼이 나타납니다. 사이드바를 닫아도 진행 중인 답변은 계속 받습니다.
- 코드 블록마다 `복사` 버튼이 있습니다. 교체안을 감싼 `<block no="...">` 태그는 빼고 본문만 복사하므로 프리셋 편집기에 바로 붙여 넣을 수 있습니다.
- 답변 속 `114번 블록`, `114번째 블록`, `블록 114`, `#114 블록`, `블록 no.114` 같은 표기와, 인라인 코드로 쓴 블록 이름(예: `` `서술 규칙` ``)은 링크가 되고, 교체안 코드 블록에는 `편집기에서 열기` 버튼이 생깁니다. 누르면 `프롬프트 V2` 편집기에서 그 블록을 선택하고 본문 입력란에 커서를 둡니다. 이후 블록 순서가 바뀌어도 답변 당시의 블록 이름으로 찾아가며, 삭제되거나 이름이 바뀌어 찾지 못하면 알려 줍니다.
- 링크를 누를 때 프로젝트의 프리셋이 사용 중이 아니면, 사용 중 프리셋을 바꿀지 먼저 묻습니다. 바꾸면 채팅에 쓰이는 프리셋도 함께 바뀝니다.

### 화면

- 사이드바는 왼쪽 가장자리를 끌어 폭을 바꿀 수 있습니다. 창이 좁아 설정 화면의 편집기가 비좁을 때는 사이드바를 288px까지 줄일 수 있고, 좁아지면 입력 안내 문구를 숨겨 내용이 잘리지 않게 합니다.
- 챗 화면뿐 아니라 설정 화면에서도 오른쪽에 남아, 조언을 보며 프리셋을 바로 고칠 수 있습니다. 화면을 오가도 받던 답변은 끊기지 않습니다.
- 다른 화면에 다녀오거나 사이드바를 다시 열거나 프로젝트를 바꾸면, 프로젝트마다 마지막으로 보던 위치로 돌아옵니다. 저장된 위치가 없으면 가장 최근 메시지의 시작 부분에서 열립니다.
- 제목줄의 접기 버튼으로 사이드바를 얇은 띠로 줄일 수 있고, 띠를 누르면 다시 펼쳐집니다. 답변을 받는 중에는 띠에 표시가 나타납니다. 완전히 끄려면 닫기 버튼이나 `Prompt Assistant` 버튼을 씁니다. `Prompt Assistant` 버튼으로 켤 때는 접혀 있던 상태와 관계없이 펼쳐서 엽니다. 휴대폰처럼 좁은 화면에서는 오른쪽 가장자리의 탭으로 남으며, 편집기로 이동할 때 자동으로 접힙니다.
- 메시지 사이 간격을 넓히고 내 질문마다 구분선을 넣었습니다.

## [기능] 캐릭터 비서

봇 전체를 분석 재료로 삼아, 필요한 부분만 골라 읽으며 대화로 수정 방향을 추천받는 우측 사이드바입니다. 개발자 도구의 `Prompt Assistant` 버튼 아래 `Character Assistant` 버튼으로 켜며, 두 비서는 한 번에 하나만 열립니다.

- **필요한 부분만 읽기:** 봇 전체를 한 번에 보내지 않습니다. 비서는 필드, 추가 인사말, 로어북, 정규식, 트리거의 목차만 먼저 보고 질문에 필요한 항목을 직접 읽거나 검색하며, 읽은 내용을 표시한 뒤 답합니다. 긴 Lua 트리거는 줄 범위로 나눠 읽습니다.
- **재료 관리:** 비서가 읽은 항목은 상단 `재료`에 남아 다음 질문에도 최신 내용으로 함께 보내집니다. 칩을 눌러 본문을 보고 X로 빼며, `자료 추가`에서 목차를 검색해 직접 넣을 수 있습니다. 예상 토큰 수가 표시됩니다.
- **범위 선택과 참고용 봇:** 기본은 대상 봇만 봅니다. `연결된 모듈`, `현재 프리셋과 토글`(토글의 현재 값 포함) 체크박스로 범위를 넓힐 수 있고, `참고용 봇`을 하나 골라 비교 자료로 쓸 수 있습니다. 참고용 봇과 모듈은 읽기 전용이라 수정 제안 대상이 아닙니다.
- **편집기로 바로 이동:** 답변 속 `로어북 12번`, `정규식 3번`, `추가 인사말 2번`, `` `설명` `` 같은 표기는 링크가 되어 캐릭터 편집기의 해당 탭을 열고, 폴더 안 로어북과 정규식은 그 항목을 펼친 뒤, 필드는 입력란에 커서를 둡니다. 순서가 바뀌어도 답변 당시의 이름으로 찾아가고, 참고용 봇과 모듈 항목은 비서 안의 보기 화면으로 엽니다.
- **수정은 직접 반영:** 비서는 칸 하나 단위로 붙여 넣을 내용을 제안하고, 긴 본문은 찾을 부분과 바꿀 내용으로 나눠 보여 줍니다. 봇을 자동으로 고치지 않습니다.
- **봇에 고정된 프로젝트:** 프로젝트는 만들 때 고른 봇에 고정되어 다른 캐릭터를 선택해도 분석 대상이 바뀌지 않으며, 메인 세이브와 별도로 저장됩니다. 비공개 라이선스 봇은 분석하지 않고, 요청 기록에는 `캐릭터 비서`로 남습니다.

## [기능] 챗 여러 개 한 번에 삭제

- 챗 목록의 각 챗 앞에 체크박스가 생겼습니다. 여러 개를 체크한 뒤 툴바의 휴지통 버튼을 누르면, 선택한 챗 이름을 확인한 다음 한꺼번에 삭제합니다. 휴지통 버튼에는 선택한 개수가 표시됩니다.
- 아무것도 체크하지 않았을 때는 이전처럼 현재 챗만 삭제합니다. 모든 챗을 선택하면 챗이 하나 이상 남아야 하므로 삭제하지 않습니다.
- 지금 보고 있던 챗이 삭제되면 남은 챗 중 첫 번째 챗으로 이동합니다.
- 챗을 하나만 지울 때도, 다음으로 열릴 챗을 아직 불러오지 않은 상태였다면 `채팅 데이터 로딩 중`에서 멈추던 문제를 고쳤습니다. 이제 삭제하기 전에 다음 챗을 먼저 불러옵니다.

## [개선] 바드위키 기억

### 시간 순서

- 응답에 원문으로 넣는 최근 턴보다 앞선 사건 제목을 오래된 순서로 최대 8개 함께 보냅니다. 항목마다 "몇 턴 전"이 붙어, 잠들기 전의 식사와 일어난 뒤의 식사처럼 비슷한 사건의 선후를 모델이 구분할 수 있습니다.
- 기억에서 찾아 넣는 사건 문서에도 몇 턴 전인지 표시합니다.

### 캐릭터 정본

- **작성 기준 (공식기본 v6):** 지식과 비밀에는 비밀, 오해, 상대가 모르는 지식처럼 이후 선택에 영향을 주는 것만 남기고, 세계 규칙과 장소 사실은 해당 문서에 한 번만 적습니다. 관계는 상대마다 현재 상태를 짧게 적고, 장면의 연대기는 사건 문서에 둡니다. 이전 지침은 `공식기본-261003-v5`로 남고, 개인 사본 프리셋은 기존 지침을 그대로 씁니다.
- **자동 정리:** 캐릭터 문서가 `자료별 검색 토큰`의 80%를 넘으면 지식과 비밀, 관계와 신뢰, 주요 전환, 장비와 소지품을 정리합니다. 그 턴의 갱신과 함께 한 번에 저장합니다. 어디로 합쳤는지 확인되지 않는 항목과 사건 문서에 같은 표현이 없는 항목은 지우지 않으며, 실제로 줄지 않으면 문서를 바꾸지 않습니다. 정리에 실패해도 이번 턴의 갱신은 저장되고 결과는 턴 영수증에 표시됩니다.
- **재정리 시점:** 정리 뒤에는 그 크기의 1.25배를 넘어야 다시 정리합니다. 줄일 것이 없던 문서는 그 크기를 새 기준으로 삼고, 모델 오류로 실패했을 때만 새 근거 메시지가 8개 쌓일 때까지 기다립니다.
- **잘라 넣기:** 정본이 `검색 목표 토큰`의 남은 자리에 다 들어가지 않으면 통째로 빼지 않고 현재 상태와 관련 있는 부분을 잘라 넣습니다.

### 기억 예산 프리셋

- 검색 예산을 절약, 보통, 넉넉, 커스텀 중에서 고릅니다. 프리셋을 고르면 검색 목표, 사건 검색, 자료별 검색, 검색 최대 토큰과 장기기억 동적 한도가 함께 맞춰지고, 직접 고치려면 커스텀을 고릅니다.
- 기본값은 보통(검색 목표 4,000 / 사건 3,000 / 자료별 2,000 / 최대 7,500, 동적 한도 절약형)입니다. 따로 설정하지 않았던 기존 사용자도 한 번 보통으로 맞춰지므로 응답마다 기억 자료가 더 들어갈 수 있습니다. 봇에 고정한 설정과 채팅별 설정은 바꾸지 않습니다.

## [개선] 챗 스크롤 위치

- 설정 화면에 다녀오거나 다른 챗으로 바꾸면 항상 마지막 메시지의 시작 부분에서 열립니다. 이전에는 이미지와 본문이 다시 그려지며 높이가 바뀌어 엉뚱한 중간 위치로 밀려 올라가곤 했습니다. 이미지가 늦게 불러와져도 위치를 유지합니다.

## [안정성] 외부 파일 변경 자동 감지 제거

Android(Termux), Docker, 리눅스에서 업데이트 직후 서버가 응답하지 않던 문제를 수정했습니다.

- **원인:** 외부 파일 변경 자동 감지는 데이터 폴더 전체를 감시했습니다. Windows와 macOS는 운영체제가 이 감시를 직접 처리하지만, 리눅스 계열에서는 Node.js가 파일마다 감시를 하나씩 걸고, 파일이 하나 생기거나 지워질 때마다 그 폴더 전체를 다시 읽습니다. 그래서 v0.9.65의 바드위키 벡터 이전처럼 파일 수만 개를 옮기는 작업이 시작되면 이 처리에 CPU가 묶여 서버가 수십 분 동안 응답하지 못했습니다.
- **변경:** 자동 감지 기능과 `설정 > 개발자`의 켜기 스위치를 없앴습니다. 예전에 켜 둔 설정이 남아 있어도 더는 감시하지 않습니다.
- **외부 편집기로 고치는 방법:** 앱(브라우저 탭)을 닫고 캐릭터 `metadata.json`, 채팅 `metadata.json` 또는 전역 로어북 JSON을 고친 뒤 다시 열면 반영됩니다. 이전에는 감시가 꺼진 상태에서 이렇게 고치면 체크섬 불일치로 불러오기가 실패했습니다. 내용은 JSON 형식과 안전성을 검사한 뒤에 받아들이며, 형식이 깨진 파일은 받아들이지도 덮어쓰지도 않고 그대로 둡니다. 이때 앱을 열면 예전처럼 `getItem Error`만 보여 주지 않고 어느 파일의 몇 번째 줄, 몇 번째 칸이 왜 잘못됐는지 알려 주므로, 그 위치를 고친 뒤 다시 열면 됩니다.
- **주의:** 앱을 켜 둔 채 고치면 반영되지 않습니다. 이때 저장은 "파일이 밖에서 바뀌었다"는 이유로 거절되며, 앱을 다시 열면 고친 내용이 적용됩니다. 캐릭터 에셋 폴더에 새로 넣은 이미지는 자동으로 등록되지 않으니 앱 안에서 추가해 주세요.

## [수정] 로어 빌더와 페르소나 빌더의 시스템 프롬프트

- 이전에는 메인 프롬프트 블록만 시스템 프롬프트로 보아, 일반 블록으로 지시문을 쓰는 프리셋에서는 `시스템 프롬프트`가 `사용할 자료 없음`으로 막혔습니다.
- 이제 현재 챗에서 쓰는 프롬프트 프리셋의 텍스트 블록을 모두 넣습니다. 블록 오버레이와 사이드바 토글 조건을 반영하고, 탈옥과 CoT 블록은 각 설정이 켜져 있을 때만 넣습니다. 바드 페인터는 이전처럼 메인 프롬프트 블록만 씁니다.

## [수정] 블록 부분 수정이 메시지 앞부분을 여는 문제

- `블록 부분 수정 활성화`를 켜고 문단 사이 여백이나 메시지 가장자리에 마우스를 올리면, 문단 하나가 아니라 메시지 전체가 블록으로 잡혀 수정 창에 메시지 앞부분이 뜨거나 엉뚱한 부분이 지워지던 문제를 고쳤습니다. 이제 여러 문단을 감싼 영역은 고르지 않고 가장 안쪽의 문단이나 제목, 인용문 같은 블록만 수정 대상으로 잡습니다.

## [수정] 챗 목록 폴더로 드래그

- 새로 만든 폴더나 다른 캐릭터로 바꾼 뒤의 폴더에 챗을 끌어다 넣을 수 없던 문제를 고쳤습니다.
- 빈 폴더는 `Empty` 글자 위에 놓으면 들어가지 않아 사실상 넣을 수 없었습니다. 이제 빈 폴더 어디에 놓아도 들어갑니다.

## [수정] 위키 프롬프트 프리셋 삭제 확인창

- 프리셋 목록에서 휴지통 버튼을 누르면 확인창이 목록 뒤에 떠서 누를 수 없던 문제를 고쳤습니다.

## [수정] 위키 리부트 중 전송 잠금 안내

- **잠긴 이유 표시:** 위키 리부트가 진행 중이거나 멈춰 있거나 실패한 챗에서는 메시지를 보낼 수 없는데, 이유가 전송 버튼의 마우스 오버 안내에만 있어 휴대폰에서는 보이지 않았습니다. 이제 입력창 위에 상태와 함께 안내가 표시됩니다. 멈춤이나 실패 상태에서는 안내에 있는 `리부트 계속`과 `리부트 취소` 버튼으로 바로 풀 수 있습니다. 실패한 경우 실패 사유도 함께 보여 줍니다.
- **다른 챗으로 옮겨 가던 잠금:** 챗 복사, 최신 메시지에서 분기, 세이브 파일 저장과 불러오기에서 끝나지 않은 위키 리부트 작업이 그대로 따라가, 리부트를 건 적 없는 챗까지 전송이 잠기던 문제를 고쳤습니다. 이미 작업이 담겨 저장된 세이브 파일도 불러올 때 작업을 지웁니다.

## [수정] 새 챗의 프롬프트 바인딩과 토글 고정 유지

- 바인딩한 챗에서 `새 채팅`을 만들면 프롬프트 바인딩과 `채팅별 프리셋 고정` 토글 값이 풀리던 문제를 고쳤습니다. 이제 페르소나처럼 직전 챗의 설정을 이어받습니다. 챗 복사, 분기, `이 위키로 새 챗 시작`과 같은 동작입니다.
