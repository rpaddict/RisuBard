# RisuBard v0.9.91

## [개선] 바드위키: 다시 나온 단역도 인물 문서로 기록
- 한 번만 나오는 단역은 지금처럼 사건 문서에만 남깁니다. 다만 그 단역이 다시 등장하거나, 다시 만났을 때 영향을 줄 상태(기절, 부상, 감금, 원한, 약속 등)가 남으면 인물 문서를 만듭니다. 그래서 감옥에서 때려 기절시킨 간수가 다음 장면에서 아무 일 없었다는 듯 나오는 일이 줄어듭니다.
- 이름이 없는 인물은 본문에서 부르는 묘사(예: 다리를 저는 사내)를 제목으로 쓰고, 나중에 이름이 밝혀지면 별칭으로 더합니다.

## [수정] 바드위키: 응답 하나에 분석 요청이 수십 번 나가던 문제
- AI 응답이 형식에 맞지 않을 때의 재시도, 추가 검색 뒤 재분석, 정본 문서 분할 재시도가 서로 겹쳐서 응답 하나에 의미 분석과 정본 갱신 요청이 수십 번 나갈 수 있었습니다. 이제 턴 하나를 분석할 때 AI 요청은 최대 10번입니다. 상한에 걸려 이번에 갱신하지 못한 정본 문서는 보류 경고로 남기고, 새 근거가 나오는 다음 턴에 다시 갱신합니다.
- 추가 검색 뒤 재분석이 실패해도, 이미 검증을 통과한 첫 분석 결과로 사건과 정본을 저장합니다. 전에는 이 경우 턴 전체가 실패로 남아 다음 응답 때 처음부터 다시 분석했습니다.
- 밀린 턴을 한 번에 분석하다가 네트워크 오류, 요청 제한, 공급자 서버 오류로 실패하면 턴을 하나씩 나눠 다시 보내지 않고 다음 응답 때 다시 시도합니다.

## [수정] 봇이 메시지를 다시 그리면 화면이 메시지 끝으로 내려가던 문제
- 봇 스크립트가 `reloadDisplay`나 `reloadChat`으로 메시지를 다시 그려 내용이 크게 바뀌면, 읽던 위치가 아니라 그 메시지의 끝으로 화면이 내려갔습니다. 첫 메시지만 있는 채팅에서 시작 화면의 버튼을 눌러 긴 오프닝으로 바뀌는 경우가 대표적입니다. 이제 첫 메시지도 읽기 위치 유지 대상에 들어가고, 다시 그리는 동안 잠깐 비는 메시지 때문에 읽기 위치를 잃지 않습니다. 읽던 문단이 사라졌으면 그 메시지의 시작에 맞춥니다.
- 새 응답이 오거나 스트리밍 중일 때 화면 끝을 따라가는 동작은 그대로입니다.

## [수정] 플러그인 모델 목록이 같은 순서로 반복해 늘어나던 문제
- 플러그인이 설정 변경 뒤 모델을 다시 등록하면(예: 모델 관리 플러그인에서 시스템 프롬프트를 바꾼 뒤 재등록), 모델 선택 화면의 `플러그인` 탭에 같은 모델 목록이 통째로 한 번 더 붙었습니다. 플러그인을 끄고 켤 때도 같은 일이 생길 수 있었습니다. 이제 같은 이름으로 다시 등록하면 기존 항목을 새 설정으로 바꾸고, 목록은 새로고침 없이도 한 벌만 남습니다.

## [수정] 로어북 항목을 옮기면 순서 숫자가 10부터 다시 매겨지던 문제
- 로어북 편집기에서 항목을 끌어 옮기거나 위아래 버튼으로 옮기면, 모든 항목의 `순서`가 목록 위치대로 10, 20, 30…으로 바뀌었습니다. 그래서 모듈 로어북에 999나 네 자리 숫자를 넣어 메인 봇 로어보다 우선하게 해도, 한 번 옮기면 다시 10부터 시작했습니다. 이제 옮겨도 직접 넣은 숫자는 그대로 남습니다.
- 목록에서 옮기는 것은 편집기에 보이는 위치만 바꿉니다. 프롬프트에 들어가는 순서를 바꾸려면 `순서` 숫자를 고치세요.
