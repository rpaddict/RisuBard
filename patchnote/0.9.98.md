# RisuBard v0.9.98

## [보안] 서버가 이 PC에서만 접속을 받음
- 지금까지 리스바드 서버는 주소를 정하지 않고 열려 유선, 무선 등 PC의 모든 네트워크에서 접속을 받았습니다. 공유기나 방화벽이 막지 않으면 다른 기기나 외부에서 리스바드를 열어 저장된 API 키를 쓸 수 있었습니다.
- 이제 기본으로 이 PC(`127.0.0.1`)에서만 접속을 받습니다. `http://localhost:7777` 접속, 설정의 원격 접속(Quick Tunnel), Tailscale은 그대로 동작합니다.
- 같은 와이파이의 휴대폰 등에서 `http://PC의IP:7777`로 직접 열어 쓰던 분은 서버를 켜기 전에 환경변수 `RISUBARD_HOST=0.0.0.0`을 설정해야 합니다. 이렇게 열면 서버 창에 경고가 표시됩니다. 되도록 원격 접속 기능이나 Tailscale을 쓰세요.
- Docker 이미지는 컨테이너 밖에서 접속해야 하므로 계속 모든 주소에서 받습니다. 외부 노출이 걱정되면 `docker-compose.yml`의 포트를 `127.0.0.1:7777:7777`로 바꾸세요.

## [추가] BardWiki를 몇 턴마다 묶어 분석
- 설정의 BardWiki 분석과 현재 챗 위키 설정에 '몇 턴마다 묶어 분석'을 추가했습니다. 기본값은 1(매 턴 분석)이며 최대 4입니다.
- 2 이상으로 두면 AI 응답이 그 수만큼 쌓일 때까지 기다렸다가 한 요청으로 묶어 분석합니다. 턴마다 반복되던 분석 지시문과 원문, 정본 갱신 요청이 줄어 보조 모델 요청 수와 토큰을 아낍니다.
- 대신 위키 반영이 그만큼 늦어집니다. 아직 분석하지 않은 최근 턴은 채팅 기록으로 답변에 들어갑니다. 기다리는 턴은 오류로 표시되지 않습니다.
- 묶은 턴이 '위키 분석 최대 길이'의 절반을 넘으면 나눠서 분석하므로, 이 값을 너무 낮추면 묶는 효과가 줄어듭니다.

## [추가] BardWiki 공식 추천 설정
- 설정의 BardWiki 분석 맨 위와 BardWiki 창의 설정에 '공식 추천 설정'을 추가했습니다. '추천값 적용' 한 번으로 보조 모델 요청과 토큰을 줄이는 값을 맞춥니다.
- 적용되는 값: 2턴마다 묶어 분석, 작업 규모 보통(32K) 이상. 작업 규모가 이미 보통보다 크면 그대로 둡니다. 과거 원문 재순위는 회수 품질을 위한 기능이라 바꾸지 않습니다.
- 이미 추천값과 같으면 버튼이 '적용됨'으로 바뀝니다. BardWiki 창에서 적용하면 지금 챗(봇에 고정했다면 그 봇)에만 저장되고, 설정 화면에서 적용하면 전역값이 바뀝니다. 설정 검색에서 '추천'으로 찾을 수 있습니다.

## [개선] 독자 게시판 되돌리기 여러 단계
- 독자 게시판의 '되돌리기'가 직전 생성 한 번이 아니라 최근 여러 번의 생성을 차례로 되돌립니다. 앞쪽 화를 고쳐 다시 연재할 때 게시판을 처음부터 새로 만들지 않아도 됩니다.
- 게시판 설정의 '되돌리기 단계'에서 1~5단계를 고릅니다. 기본값은 3이며 게시판마다 따로 정합니다. 되돌릴 수 있는 횟수는 버튼에 `되돌리기 (3)`처럼 표시됩니다.
- 한 번 누른 생성이 하나의 단계입니다. 여러 화를 한 번에 연재했다면 그 화들이 함께 되돌아갑니다.
- 생성 사이에 작가 글 쓰기, 화 지우기처럼 게시판을 직접 바꾸면 그 이전 생성으로는 되돌릴 수 없습니다. 직접 바꾼 내용이 사라지지 않게 하기 위해서입니다.

## [수정] PC에서 사이드바로 연 창이 채팅 화면 뒤에 가려지던 문제
- 0.9.97부터 PC 화면에서 캐릭터 사이드바의 메인/보조 모델 선택처럼 사이드바에서 연 창이 채팅 화면 뒤에 깔려 보이지 않던 문제를 고쳤습니다. 창 폭을 줄여 사이드바가 화면 위에 겹쳐 뜨는 배치에서만 보였습니다.
- 0.9.97에서 너비 조절 손잡이가 봇 패널 위로 보이지 않게 하려고 사이드바 패널을 따로 묶었는데, 이 때문에 패널에서 연 창까지 채팅 화면 아래에 갇혔습니다. 이제 패널은 묶지 않고 손잡이만 순서대로 그려서, 사이드바에서 연 창은 맨 앞에 뜨고 봇 패널은 여전히 손잡이를 덮습니다.

## [수정] PageFold Gemini의 BardWiki 정본 갱신마다 실패 요청이 한 번씩 나가던 문제
- PageFold Gemini 모델로 BardWiki 정본을 갱신하면, 매번 먼저 보낸 요청이 '요청 인자 거부'로 실패한 뒤 같은 내용을 다시 보내던 문제를 고쳤습니다. 정본 갱신 한 번에 요청이 두 번씩 나가고 실패한 요청만큼 십여 초씩 늦어졌습니다.
- 이제 의미 분석과 같이 처음부터 이 모델이 받아들이는 방식으로 보내므로 실패 요청 없이 한 번에 처리합니다. 저장 전에 응답 형식을 검사하는 과정은 그대로입니다.

## [수정] 추론만 하고 본문 없이 끝난 응답이 빈 답변으로 남던 문제
- Gemini 3.8 Flash 등에서 모델이 추론(사고)만 보내고 본문 없이 끝나면, 채팅에 추론만 있는 빈 답변이 남던 문제를 고쳤습니다.
- 이제 이런 응답은 설정의 '실패 시 재요청 횟수'만큼 자동으로 다시 요청합니다. 스트리밍 중이면 새 응답이 같은 메시지 자리에 이어서 표시됩니다. 재시도를 모두 써도 본문이 없으면 마지막 응답을 그대로 남깁니다.
- '빈 응답 시 대체'를 켠 경우 추론만 있는 응답도 빈 응답으로 보고 대체 모델로 넘어갑니다.
- 모델이 쓰는 도구(MCP)가 켜져 있으면 도구가 두 번 실행되지 않도록 다시 요청하지 않습니다. 프리셋이 직접 태그를 지정한 추론은 대상이 아닙니다.

## [수정] BardWiki 설정 창이 왼쪽에서 잘리던 문제
- 캐릭터 사이드바를 연 채 BardWiki 창의 설정을 열면, 넓은 설정 창의 왼쪽 부분이 사이드바 아래로 잘려 보이지 않던 문제를 고쳤습니다. 이제 설정 창은 채팅 영역 안에 들어오는 폭으로 열립니다.
