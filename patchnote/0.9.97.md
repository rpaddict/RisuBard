# RisuBard v0.9.97

## [추가] 과거 원문 재순위에 리랭커 API 사용
- 바드위키 `과거 원문 재순위`를 보조 모델 대신 리랭커 API로 돌릴 수 있습니다. 설정 > 공통 설정 > 채팅 응답의 `과거 원문 재순위 방식`에서 `리랭커 API`를 고르고 URL, API 키, 모델을 넣으면 됩니다.
- Cohere 방식의 `/rerank` 요청을 보내므로 Cohere, Jina, Infinity 같은 로컬 서버를 쓸 수 있습니다. 주소가 `/rerank`로 끝나지 않으면 자동으로 붙입니다.
- 리랭커는 점수만 매기므로 `최소 관련도`보다 낮은 원문은 버리고, 남은 원문 중 상위 4개만 위키 문서보다 먼저 넣습니다. 점수 범위는 모델마다 다르니 엉뚱한 원문이 들어오면 값을 올리고, 맞는 원문이 빠지면 내리세요.
- 리랭커는 모델 재순위와 달리 출력 한도에 걸려 `AI 응답이 출력 한도에서 잘렸습니다`로 건너뛰는 일이 없고, 더 빠르고 저렴합니다. 요청이 실패하면 지금처럼 기존 검색 결과를 그대로 씁니다.

## [추가] 개발 도구에서 채팅 변수 직접 추가
- 캐릭터 사이드바 개발 도구의 `Variables` 목록 아래에 이름과 값을 넣고 `+`(또는 Enter)로 현재 채팅에 새 변수를 만들 수 있습니다. 아직 한 번도 설정되지 않은 변수도 미리 넣어 두고 조건 분기를 시험할 수 있습니다.
- 이름 앞의 `$`는 붙여도 되고 빼도 됩니다. 이미 있는 이름이면 버튼이 꺼지며, 그 값은 목록에서 바로 고치면 됩니다.
- 같은 개발 도구에 `Lua Variables` 칸이 생겼습니다. 현재 봇과 켜진 모듈의 Lua에서 읽고 쓰는 채팅 변수를 모아 이름, 읽기와 쓰기 횟수, 코드 줄 번호, 현재 값을 보여 줍니다. `ST.var(id,'이름')`처럼 변수를 감싼 함수로 읽어도 따라가서 찾습니다.
- 변수 이름으로 시작하거나 변수 이름을 언급한 주석, 호출한 줄 끝의 주석을 설명으로 붙여 줍니다. 세 줄이 넘는 설명은 눌러서 펼칩니다. 이름이나 주석 내용으로 검색하고, 아직 값이 없는 변수만 골라 보고, `Add`로 바로 만들 수 있습니다.

## [개선] 캐싱 친화적 구조에서 지난 대화도 캐시가 유지됨
- `캐싱 친화적 구조`를 켜도 지난 대화는 매 턴 가장 오래된 응답이 하나씩 빠져, 대화 기록 구간이 매번 프롬프트 캐시에서 빗나갔습니다. 바드위키 기억을 뒤로 옮겨도 캐시 할인은 프리셋과 캐릭터 설명 부분에만 적용됐습니다.
- 이제 이 옵션이 켜져 있으면 지난 대화를 `답변에 넣을 응답 수`의 절반 단위로 한꺼번에 뺍니다. 12개 설정이면 12~17개를 유지하다가 18개가 되는 턴에 6개를 빼고 다시 12개부터 쌓습니다. 빼는 턴 외에는 대화 기록 앞부분이 그대로라 캐시가 계속 적중합니다.
- 첫 인사말도 첫 묶음과 같은 턴에 빠지므로 캐시 미스가 따로 생기지 않습니다. 대신 평균적으로 지난 대화가 조금 더 길게 들어갑니다. 옵션을 끄면 이전처럼 한 개씩 뺍니다.

## [개선] 앱 스킨 파일을 끌어 놓아 설치
- `.risuskin` 파일을 봇이나 모듈처럼 앱 화면에 끌어 놓으면 바로 설치되고 적용됩니다. 설정 > 환경 > 앱 스킨에 들어가지 않아도 됩니다.
- 같은 이름의 스킨이 이미 있으면 바꿀지 먼저 묻습니다. 형식이 잘못된 파일은 이유를 알려 주고 설치하지 않습니다. 다른 스킨으로 돌아가려면 설정 > 환경 > 앱 스킨에서 고르면 됩니다.

## [개선] 프리셋 토글 그룹을 다른 버튼과 구분
- 채팅 사이드바의 프롬프트 프리셋 토글 그룹(예 `바드프롬 코어`, `야스`)이 `챗 목록` 같은 다른 접기 칸이나 버튼과 똑같이 보여 어떤 옵션이 어느 그룹에 속하는지 알기 어려웠습니다.
- 이제 그룹 제목줄은 모델 선택 버튼과 같은 색으로 채워지고, 펼친 안쪽은 그 색을 옅게 깔아 그룹 범위가 드러납니다. 그 안의 입력칸은 한 단계 어두운 면으로 내려가 그룹 배경과도 구분됩니다.
- 간단 사이드바에서 그룹 밖 토글이 한 줄에 몇 개뿐이면 빈 칸 자리를 남겨 그룹 안 토글보다 짧게 보이던 문제를 고쳤습니다. 이제 남은 폭을 나눠 채워 줄 끝까지 늘어납니다.
- 색은 지금 쓰는 앱 스킨과 색 구성을 그대로 따릅니다. 스킨 제작자는 새 `toggle-group` 파트로 이 그룹을 따로 꾸밀 수 있습니다.

## [수정] OpenRouter 보조 모델에서 위키 반영이 `Provider returned error`로 멈추던 문제
- OpenRouter로 보조 모델을 쓸 때 일부 제공사가 바드위키의 구조화 출력(JSON 스키마) 요청을 이유 없이 거절하면, `Memory analysis model request failed: 요청 에러:Provider returned error`가 나며 정본 반영이 매 턴 실패하던 문제를 고쳤습니다. 이 오류는 다른 스키마 거절과 달리 프롬프트 방식 재시도로 넘어가지 않았습니다.
- 이제 이 오류가 나면 스키마를 프롬프트에 넣는 방식으로 한 번 더 요청합니다.
- OpenRouter 오류에는 실제 제공사 이름과 거절 원문도 함께 표시합니다. 그동안은 `Provider returned error`만 보여 원인을 알 수 없었습니다.

## [수정] 보조 모델 재순위가 출력 한도에서 잘리던 문제
- 추론(thinking) 모델로 `과거 원문 재순위`를 쓰면 `RisuBard source rerank skipped` 경고와 함께 `AI 응답이 출력 한도에서 잘렸습니다`가 나며 재순위가 매번 건너뛰어지던 문제를 고쳤습니다. 출력 한도가 512토큰으로 고정되어 있어 모델이 생각하는 데 한도를 다 써 버렸기 때문입니다.
- 이제 다른 바드위키 분석 요청과 같이 고급 설정의 `분석 토큰 상한`을 따릅니다. 실제 답은 짧으므로 비용은 거의 늘지 않습니다.

## [수정] 정상 종료된 응답이 빈 응답으로 버려지던 문제
- 모델 프리셋으로 채팅할 때 응답이 `<think>`로 시작하고 닫는 태그가 없으면, 본문이 길게 와도 전부 생각으로 보고 `AI가 최종 답변 없이 빈 응답을 반환했습니다` 오류를 내던 문제를 고쳤습니다. 프록시가 생각 내용을 본문에 섞어 보낼 때 주로 생겼습니다.
- 이제 정상 종료된 응답은 그대로 받습니다. 생각만 있고 본문이 없는 응답이나 출력 한도에서 잘린 응답은 지금처럼 오류로 처리합니다.

## [수정] 홈 화면 RisuRealm 표시를 드롭다운으로 고르기
- `RisuRealm 접힘으로 시작`을 켜도 홈 화면의 RisuRealm이 항상 펼쳐진 채 뜨던 문제를 고쳤습니다. 설정값은 저장됐지만 홈 화면이 이 값을 읽지 않았습니다.
- 설정 > 환경 > 디스플레이 > 기타의 `RisuRealm` 드롭다운에서 `기본 표시`, `접힘으로 시작`, `임시 제거` 중 하나를 고릅니다. 예전에 접힘으로 시작을 켜 둔 경우 `접힘으로 시작`으로 이어집니다.
- `접힘으로 시작`은 홈 화면에 RisuRealm 제목줄만 보여 주고, `펼치기`를 누르기 전까지 RisuRealm 목록을 불러오지 않습니다. 펼친 뒤에는 `접기`로 다시 접을 수 있습니다.
- `임시 제거`는 홈 화면에서 RisuRealm을 아예 빼고 불러오지도 않습니다. 다음에 앱을 열어도 그대로이며, 드롭다운을 다시 바꾸면 바로 돌아옵니다.

## [수정] 사이드바 너비 조절 손잡이가 봇 화면 위로 보이던 문제
- 봇의 FAB 버튼 등으로 연 전체 화면 패널 위로 왼쪽 사이드바의 너비 조절 손잡이가 겹쳐 보이던 문제를 고쳤습니다. 손잡이와 새 캐릭터 배지 같은 사이드바 안 요소의 표시 순서가 채팅 화면 바깥으로 새어 나와 봇 패널보다 위에 그려졌기 때문입니다.
- 이제 사이드바 안 요소는 사이드바 안에서만 순서를 다투므로 채팅 화면에 뜬 패널이 사이드바를 덮으면 손잡이도 함께 가려집니다. 손잡이 조작은 그대로입니다.
