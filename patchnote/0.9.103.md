# RisuBard v0.9.103

## [실험] Claude와 Gemini에서 시스템 프롬프트 캐시가 깨지지 않게 하는 옵션
- 모델 프리셋을 Claude(Anthropic)나 Gemini 방식으로 연결하면, 요청 안의 시스템 역할 블록을 위치와 상관없이 모두 맨 앞 시스템 프롬프트로 모아 보냈습니다. 채팅 기록 뒤에 있는 키워드 로어, 바드위키 기억, 작가의 노트도 시스템 프롬프트로 올라갔습니다.
- 이런 블록은 매 턴 바뀌므로 시스템 프롬프트도 매 턴 달라졌습니다. 프롬프트 캐시는 앞에서부터 같은 구간까지만 적중하는데 시스템 프롬프트가 요청의 맨 앞이라, 프리셋과 지난 대화까지 매번 캐시를 놓쳤습니다. `캐싱 친화적 구조`로 바드위키 기억을 뒤로 옮겨도 같은 이유로 효과가 없었습니다.
- `환경설정 > 공통 설정 > 채팅 응답`에 '대화 뒤쪽 시스템 블록을 제자리에 유지 (실험)' 스위치를 추가했습니다. 켜면 첫 대화 메시지 앞에 있는 시스템 블록만 시스템 프롬프트로 보내고, 그 뒤의 블록은 프리셋이 둔 자리에 `System: `을 붙인 유저 메시지로 보냅니다.
- 기본값은 꺼짐입니다. 모델이 보는 프롬프트 구조가 바뀌므로 켠 뒤에 응답을 확인해 주세요. OpenAI 호환 방식은 원래 제자리에 보내므로 바뀌지 않습니다.

## [실험] 항상 활성화 로어를 채팅 기록 앞에 배치, 환경설정으로 복귀
- 0.9.102에서 뺐던 '항상 활성화 로어를 채팅 기록 앞에 배치 (실험)' 옵션을 다시 넣었습니다. 이번에는 로어북 사이드바가 아니라 `환경설정 > 공통 설정 > 채팅 응답`의 `캐싱 친화적 구조` 바로 아래에 있습니다.
- 켜면 항상 활성화 로어북 항목을 프리셋의 로어북 블록 대신 페르소나 바로 뒤, 채팅 기록 앞에 넣습니다. 매 턴 내용이 같은 항목이 프롬프트 캐시 구간에 들어갑니다.
- 키워드로 불려온 항목과 `@@depth`, `@@position`처럼 위치를 직접 지정한 항목은 그대로 둡니다. 프리셋의 로어북 블록이 채팅 기록 뒤에 있을 때만 동작합니다.
- 기본값은 꺼짐입니다. 전에 켜 두었던 분은 켜진 상태로 돌아옵니다.

## 바드위키 정본 저장 실패가 끝없이 반복되던 문제
- 이미 분석한 턴을 다시 분석하면(다시 시도, 리롤, 수정 등) 그 턴의 사건 문서 제목이 새로 정해지고, 그 사건을 링크하던 인물 문서의 링크도 새 제목으로 고쳐집니다. 그런데 같은 분석의 정본 갱신이 링크를 고치기 전의 문서를 기준으로 저장하려 해서, 문서가 그사이 바뀌었다고 보고 `정본 문서 저장 실패`로 끝났습니다.
- 다시 시도할 때마다 사건 제목이 또 바뀌므로 같은 인물들에서 매번 실패했고, 실패한 턴이 대기열에 남아 뒤의 턴까지 쌓이며 위키에 반영되지 않았습니다.
- 이제 사건 제목이 바뀌면 링크가 고쳐진 인물 문서를 다시 읽은 뒤 정본을 갱신합니다. 이미 밀린 턴은 업데이트 후 '다시 시도'를 누르면 반영됩니다.

## 바드위키 화면 정리
- 문서 편집 화면의 검색어, 작중 시간, 출처 메시지 수, 마지막 수정 시각 줄을 없애고 '타입' 왼쪽의 정보 아이콘 안으로 옮겼습니다. 아이콘에 마우스를 올리면 잠깐 보이고, 누르면 고정됩니다. 다시 누르거나 바깥을 누르거나 Esc를 누르면 닫힙니다.
- 원문으로 이동, 컨텍스트 포함 설정, 저장 같은 도구 버튼이 한 줄에 다 들어가지 않을 때 오른쪽으로 밀려 가로 스크롤되던 문제를 고쳤습니다. 이제 다음 줄로 넘어가 모든 버튼이 보입니다.
- 바드위키 창에 독자 게시판처럼 '접기'와 '닫기' 버튼을 따로 두었습니다. 전에는 접기 모양 아이콘을 눌러도 창이 닫혔습니다. 이제 접기를 누르면 작업 상태를 그대로 둔 채 오른쪽에 세로 띠만 남고, 띠를 누르면 원래 폭으로 다시 펼쳐집니다. 독자 게시판과 나란히 접고 펴며 쓸 수 있습니다.

## 독자 게시판에 OOC 턴을 연재하지 않음
- `<!-- OOC_turn -->`이 붙은 OOC 턴 응답은 이제 독자 게시판 연재 본문에 들어가지 않습니다. 연재할 남은 응답 수와 '나눠 연재'의 한 화 분량을 셀 때도 빠집니다. 범위 안에 OOC 턴밖에 없으면 새 화를 올리지 않습니다.
- 연재 범위의 턴 번호는 채팅에 보이는 턴 번호와 같게 OOC 턴도 계속 셉니다. 이미 OOC 턴이 들어간 채 올라간 화는 그대로 두며, 내려간 화로 처리되지 않습니다.

## 독자 게시판 추측 정리
- 독자의 추측이 '맞음', '틀림'으로 판정된 뒤에도 지워지지 않고 끝없이 쌓이던 문제를 고쳤습니다. 이제 독자마다 작품별로 아직 판정되지 않은 추측 최근 6개와 판정된 추측 최근 2개만 남깁니다.
- 이 범위는 AI가 독자 반응을 만들 때 참고하는 범위와 같습니다. 그보다 오래된 추측은 원래 AI가 보지 못해 판정될 수 없었으므로, 독자 반응에는 영향이 없습니다. 이미 쌓인 추측도 게시판을 불러올 때 같은 기준으로 정리됩니다.
- 게시판 관리 화면의 독자 목록에는 남은 추측이 모두 보입니다. 전에는 최근 6개만 보여서 판정된 추측에 아직 살아 있는 추측이 가려질 수 있었습니다.

## 모듈 교체 업데이트에서 '(업데이트 전)' 사본을 남기지 않음
- 모듈을 기존 모듈 교체로 업데이트하면 이름 끝에 '(업데이트 전)'이 붙은 사본을 모듈 목록에 남겼습니다. 이제 사본을 만들지 않고 기존 모듈만 새 버전으로 바꿉니다.
- 이전 버전에서 남은 '(업데이트 전)' 사본은 그 모듈을 다음에 업데이트할 때 함께 지워집니다. 지금 바로 정리하려면 모듈 목록에서 직접 삭제하면 됩니다.
- 봇 업데이트는 전처럼 업데이트 전 상태를 휴지통에 3일 동안 보관합니다.

## 사이드바 열기/닫기 버튼이 봇 창을 덮던 문제
- 채팅 화면 왼쪽 위의 사이드바 열기/닫기 화살표 버튼이 봇이 띄운 메뉴 창(FAB 패널 등) 위에 겹쳐 보이던 문제를 고쳤습니다. 이제 봇 창이 열려 있으면 버튼이 그 아래로 들어갑니다.
- 바드위키 창과 앱 사이드바는 전처럼 봇 창보다 위에 표시됩니다.

## 봇 FAB 버튼이 바드위키와 독자 게시판에 가려지던 문제
- 바드위키나 독자 게시판을 열면 봇이 화면 가장자리에 띄운 FAB 버튼과 패널이 그 창 아래로 들어가 가려졌습니다. 이제 오른쪽 스크롤 이동 버튼처럼 채팅 화면의 가장자리를 따라 함께 밀려나 계속 보이고 누를 수 있습니다.
- 왼쪽 앱 사이드바를 열었을 때도 왼쪽에 붙은 봇 버튼이 사이드바 아래로 숨지 않습니다. 봇 패널을 가운데에 띄우는 봇은 이제 화면 전체가 아니라 채팅 화면의 가운데에 띄워집니다.
- 플러그인이 추가한 떠 있는 버튼도 같은 기준으로 채팅 화면 안에 배치됩니다.

## 채팅 사이드바 접이식 섹션의 열림 상태 기억
- 봇 채팅 사이드바의 챗 목록과 프롬프트 토글 그룹(`OOC 모드`, `바드프롬 코어` 같은 접이식 묶음)이 다른 봇이나 다른 화면을 보고 오거나 앱을 다시 켜면 모두 닫혔습니다. 이제 봇마다 마지막으로 열고 닫은 상태를 기억해 그대로 보여 줍니다.
- 이 상태는 지금 쓰는 브라우저(또는 앱)에만 저장되며 봇 데이터에는 들어가지 않습니다. 그래서 섹션을 여닫아도 저장이 일어나지 않고, 다른 기기에서는 따로 기억됩니다.

## 챗 목록 머리글에 현재 챗 제목 표시
- 사이드바 맨 위에 따로 있던 현재 챗 제목 줄을 없애고, 그 제목을 챗 목록 섹션의 머리글로 옮겼습니다. 제목은 테마 강조색으로 표시되고, 오른쪽 열기/닫기 화살표 옆에 '목록'이 작게 붙습니다.
- 제목이 길면 한 줄에서 말줄임표로 줄이며, 마우스를 올리면 전체 제목이 보입니다.

## 사이드바에 스킨 버튼 추가
- 봇 채팅 사이드바 맨 아래의 긴 '모듈' 버튼을 '모듈'과 '스킨' 두 버튼으로 나눴습니다. '스킨'을 누르면 모듈 창이 스킨 탭으로 바로 열려, 이 봇에 쓸 앱 스킨을 고를 수 있습니다.
- 이 봇에 고정한 스킨이 있으면 '스킨' 버튼이 프롬프트 고정 버튼처럼 강조색으로 바뀝니다. 마우스를 올리면 고정된 스킨 이름이 보입니다.

## 앱 밖에서 넣은 모듈 그림을 재시작 없이 읽음
- 외부 도구가 앱이 켜져 있는 동안 데이터 폴더의 그림 저장소(`asset-store`)에 그림 파일을 넣으면, 앱을 다시 시작할 때까지 그 그림이 보이지 않았습니다. 앱이 저장소의 파일 목록을 시작할 때 한 번만 읽었기 때문입니다.
- 이제 목록에 없는 그림을 요청받으면 저장소 폴더를 한 번 더 확인하고, 파일이 있으면 바로 씁니다. 파일 이름이 곧 내용의 해시라서, 내용이 이름과 맞지 않는 파일은 전처럼 거부합니다.

## 미니멀 모드에서 잘린 이름을 툴팁으로 확인
- 사이드바 미니멀 모드의 메인 모델, 보조 모델 칸에 마우스를 올리면 '모델' 같은 칸 이름만 보였습니다. 이제 `메인 모델: Google Cloud Gemini Flash 3 Preview`처럼 칸 이름과 실제 모델의 전체 이름이 함께 보입니다. 모델 프리셋 모드에서는 연결된 모델 프리셋 이름이 보입니다.
- 프롬프트 토글의 선택 칸과 글자 입력 칸도 마우스를 올리면 `Era 시점: 3인칭`처럼 토글 이름과 지금 고른 값을 보여 줍니다. 칸이 좁아 고른 값이 잘려도 툴팁에서 끝까지 읽을 수 있습니다.
