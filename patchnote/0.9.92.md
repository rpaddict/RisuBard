# RisuBard v0.9.92

## [개선] 프롬프트 프리셋 창: 끌어서 여러 개 선택, 선택 항목 한 번에 삭제
- 체크박스를 누른 채 위아래로 끌면 지나간 항목이 모두 같은 상태로 바뀝니다. 꺼진 칸에서 시작하면 모두 선택하고, 켜진 칸에서 시작하면 모두 해제합니다. 목록 위아래 끝으로 끌면 목록이 따라 내려가며 계속 선택합니다.
- Shift를 누른 채 체크박스를 누르면 마지막으로 누른 항목부터 그 항목까지 한 번에 선택합니다.
- 선택한 프리셋을 `선택 항목 삭제` 버튼으로 한 번에 지울 수 있습니다. 지우기 전에 개수를 확인하고, 모든 프리셋을 선택했을 때는 지우지 않습니다(프리셋은 하나 이상 남아야 합니다).
- 같은 정리 목록을 쓰는 모듈, 플러그인, 바드위키 프롬프트 화면에서도 끌어서 선택과 Shift 범위 선택이 됩니다.

## [개선] 앱 스킨 준비: 모서리, 그림자, 글꼴을 변수 하나로 바꿀 수 있게
- 앱 전체의 모서리 둥글기, 그림자, 글꼴이 이제 CSS 변수를 따릅니다. 화면은 지금과 똑같고(주요 화면에서 요소별 계산값을 비교해 차이 없음을 확인), 나중에 나올 앱 스킨의 바탕이 됩니다.
- 커스텀 CSS에서 `:root`에 아래 변수를 넣으면 앱 전체에 바로 적용됩니다.
  - 모서리: `--risu-radius-xs` ~ `--risu-radius-4xl`, `--risu-radius`
  - 그림자: `--risu-shadow-2xs` ~ `--risu-shadow-2xl`, `--risu-shadow`, `--risu-shadow-popover`(드롭다운)
  - 글꼴: `--risu-font-ui`(앱 화면), `--risu-font-prose`(채팅 본문), `--risu-font-display`, `--risu-font-numeric`. 채팅 본문 글꼴만 따로 바꿀 수 있고, 봇이 직접 지정한 글꼴은 전처럼 봇 쪽이 우선합니다.
- 사용자 지정 색 구성에서 그림자 색을 바꾸면 이제 앱의 모든 그림자가 그 색을 따릅니다. 기본 색 구성은 검은 그림자 그대로입니다.
- 커스텀 CSS가 내부 클래스 이름 대신 겨눌 수 있는 고정 훅을 붙였습니다. 앱이 업데이트돼도 이름이 바뀌지 않는 약속된 이름입니다.
  - `data-skin-part`: `app-shell`, `sidebar-rail`, `rail-icon`, `sidebar-panel`, `chat-screen`, `message`, `composer`, `composer-field`, `button`, `input`, `switch`, `checkbox`, `chip`, `tabs`, `tab`, `modal`, `menu`, `settings-nav`, `settings-page`
  - 상태와 종류: `data-skin-state`(`active`, `checked`), `data-skin-role`(메시지의 `user`, `bot`), `data-skin-variant`(버튼과 칩 종류)
  - 예: `[data-skin-part="tab"][data-skin-state="active"] { box-shadow: inset 0 -3px 0 orange; }`

## [추가] 앱 스킨: 설치하고 골라서 앱 모양을 통째로 바꾸기
- 설정 > 환경 맨 위에 `앱 스킨`이 생겼습니다. 스킨 파일(.risuskin)을 가져오거나 스킨 코드를 붙여넣어 설치하고, 카드를 눌러 바로 바꿉니다. `기본`을 고르면 지금까지의 화면으로 돌아갑니다.
- 스킨 하나에 색, 채팅 본문 글자색, 모서리, 그림자, 글꼴 이름과 부품 모양(위 고정 훅을 겨눈 CSS)을 담습니다. 스킨이 색을 정하면 아래 색상 팔레트보다 스킨 색이 먼저 보입니다.
- 설치할 때 스킨을 검사합니다. 내부 클래스나 id를 겨눈 CSS, 외부 주소, 스크립트, `position: fixed`, 앱 부품을 숨기는 선언은 이유와 함께 거절합니다. 그래서 스킨이 앱을 깨거나 개인정보를 밖으로 보낼 수 없습니다.
- 스킨 때문에 화면이 이상하면 주소 끝에 `?safeskin=1`을 붙여 열면 기본 화면으로 시작합니다. 안전 모드에서도 스킨은 꺼집니다. 저장된 스킨이 손상되면 알림을 띄우고 기본 화면으로 보여 줍니다.
- 테마 프리셋에 고른 스킨도 함께 저장되어, 프리셋을 바꾸면 스킨도 바뀝니다.
- 스킨에 글꼴을 역할별로 적을 수 있습니다(`fonts`: 앱 화면, 채팅 본문, 제목, 숫자). 컴퓨터에 없는 글꼴은 역할별 기본 글꼴로 대신 보입니다. 제목과 숫자는 앱 화면 글꼴로, 앱 화면과 채팅 본문은 기본 글꼴로 넘어갑니다.
- 설정 > 환경 > 앱 스킨에서 고른 스킨의 글꼴마다 `설치됨`, `없음`, `스킨에 들어 있음`을 보여 주고, 없는 글꼴은 스킨이 적어 둔 `받기` 링크를 띄웁니다. 브라우저가 설치 글꼴 확인을 막으면 `확인 불가`로 표시합니다.
- 이 기기에 없는 글꼴이 있는 스킨은 카드 왼쪽 위에 노란 `⚠ 개수` 표시가 붙습니다. 그런 스킨을 적용하면 없는 글꼴 이름과 설치 안내를 담은 경고가 한 번 뜹니다. 같은 스킨과 같은 글꼴이면 이 기기에서 다시 띄우지 않고, 테마 프리셋으로 바뀔 때도 똑같이 알려 줍니다.
- 글꼴 파일(woff2, woff, ttf, otf, 4MB 이하)을 스킨 파일에 넣을 수도 있습니다. 설치할 때 글꼴은 에셋 저장소로 옮겨 설정 저장이 무거워지지 않고, 스킨을 내보내면 다시 파일 안에 담깁니다. 에셋 자동 정리가 켜져 있어도 스킨 글꼴은 지우지 않습니다.
- 스킨 CSS에서 `::before`, `::after` 장식은 숨길 수 있습니다(예: 탭의 기본 밑줄을 지우고 다른 표시로 바꾸기). 앱 부품 자체를 숨기는 선언은 여전히 거절합니다.
- 스킨을 만드는 사람은 `pnpm check:skin <파일>`로 앱이 설치할 때와 같은 검사를 미리 돌릴 수 있습니다.
- 화면마다 따로 적혀 있던 모서리 둥글기 500곳과 그림자 41곳도 스킨을 따르게 바꿨습니다. 이제 스킨이 모서리를 0으로 정하면 설정, 채팅, 홈, 프롬프트 프리셋 창, 캐릭터 저장소 같은 창의 모서리가 모두 각지게 바뀝니다(원형 버튼과 알약 모양 버튼은 그대로). 기본 화면은 예전과 같습니다.
- 스킨에서 그림자를 크기별로 한 번에 바꾸는 `shadow-raised`(작은 그림자), `shadow-floating`(떠 있는 카드), `shadow-overlay`(창과 서랍) 토큰을 쓸 수 있습니다.
- 채팅 메시지 카드에 `message-card` 훅을 붙였습니다. 스킨이 메시지 줄 전체가 아니라 눈에 보이는 카드 자체에 테두리, 그림자, 무늬를 줄 수 있습니다.
- 스킨 검사가 부품의 크기나 위치를 바꾸는 선언(테두리 굵기, 안쪽 여백, 바깥 여백, 글꼴, 자간, 기울이기 등)을 찾아 경고합니다. 이런 선언은 스킨이 손대지 않은 옆 요소와 글자 줄을 어긋나게 하므로, 테두리는 `box-shadow`로, 강조는 색과 배경으로 바꾸라고 알려 줍니다. 제목(`h1`~`h6`)과 `::before`, `::after` 장식, 누르거나 올렸을 때의 움직임은 경고하지 않습니다.
- 샘플 스킨 두 개를 새로 만들었습니다. 강철 전술은 전술 지도 격자, 강철 판 레일, 모서리를 깎은 주황 버튼, 창 네 귀퉁이의 조준 괄호를, 히어로 코믹은 빨간 망점 레일, 집중선 배경, 흰 테두리와 먹선의 만화 컷 메시지, 누르면 그림자로 들어가는 버튼을 보여 줍니다. 두 스킨 모두 부품 크기는 바꾸지 않고 색, 배경, 그림자, 잘라 내기(`clip-path`)만으로 그렸습니다.

## [수정] 화면 여백과 줄 맞춤
- 설정 화면에서 앱 스킨, 색상 팔레트, 사용자 지정 배경 같은 묶음 안 항목이 테두리에 바짝 붙어 있던 문제를 고쳤습니다. 이제 다른 설정 줄과 같은 좌우 여백으로 맞춰집니다.
- 바드위키 문서 머리의 `검색어` 줄이 왼쪽 테두리에 붙어 있던 문제를 고쳤습니다. 아래 출처 줄과 같은 여백으로 맞춰집니다.
- 바드위키 문서 도구 줄이 좁을 때 왼쪽의 `원문으로 이동` 버튼이 잘려 보이지 않던 문제를 고쳤습니다. 넘치면 오른쪽으로 밀어서 볼 수 있습니다.
- 스킨 코드 붙여넣기로 같은 id의 스킨을 다시 설치할 때, 바꿀지 묻는 창이 붙여넣기 창 뒤에 가려 누를 수 없던 문제를 고쳤습니다.
